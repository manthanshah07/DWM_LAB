Data Warehousing and Mining (DWM) — Experiment 04¶

Experiment Title: Simple and Multiple Linear Regression for Next-Session Stock Return Prediction¶

Dataset: stock_market_data.csv (3 Years of Daily NSE Trading Data across 20 Major Indian Equities)

1. Objectives & Theoretical Formulation¶

  • Core Objective: Implement Simple Linear Regression (SLR) and Multiple Linear Regression (MLR) on large-cap equity market data to predict the next trading session's close-to-close percentage return (Next_Day_Return), and rigorously evaluate out-of-sample performance against an unbiased Zero-Return Baseline using Mean Absolute Error ($\text{MAE}$), Root Mean Squared Error ($\text{RMSE}$), and the Coefficient of Determination ($R^2$ Score).
  • Mathematical Target Variable ($y$): $$\text{Next\_Day\_Return}_{t+1} = \left( \frac{\text{Close}_{t+1} - \text{Close}_t}{\text{Close}_t} \right) \times 100$$ This represents the forward percentage return realized on session $t+1$ relative to session $t$.
  • Per-Ticker Chronological Feature Space ($X$): All predictive features are computed strictly per-ticker in datetime order, ensuring zero cross-ticker contamination and zero forward lookahead bias:
    1. $\text{Lag1\_Return}_t = \left( \frac{\text{Close}_t - \text{Close}_{t-1}}{\text{Close}_{t-1}} \right) \times 100$: Prior close-to-close return ending at session $t$.
    2. $\text{Lag1\_Intraday}_t = \left( \frac{\text{Close}_t - \text{Open}_t}{\text{Open}_t} \right) \times 100$: Prior session intraday price momentum (Open-to-Close).
    3. $\text{Lag1\_Volatility}_t = \left( \frac{\text{High}_t - \text{Low}_t}{\text{Open}_t} \right) \times 100$: Prior session intraday trading range (spread).
    4. $\text{Lag1\_Volume\_Log}_t = \ln(1 + \text{Volume}_t)$: Log-transformed trading activity.
    5. $\text{SMA5\_Return}_t$: 5-session rolling moving average of past daily percentage returns.
  • Unified Evaluation Protocol & Boundary Purging:
    • Common supervised population across all experiments (14,680 observations, 734 unique trading dates).
    • Datetime-based chronological 80:20 partition across unique calendar dates.
    • To prevent temporal label overlap across the boundary, a 1-session purge is applied on 2026-03-06: the test set starts strictly after the maximum training target realization date.
    • Verification: $\max(\text{Train Target Date}) < \min(\text{Test Feature Date})$.

3. Data Ingestion, Datetime Handling & Purged Temporal Split¶

Ingest stock_market_data.csv, parse dates into Date_dt, compute chronological lagged features and forward return targets per ticker, apply the common evaluation eligibility filter, and perform a purged chronological 80:20 split.

# 1. Ingest dataset and parse dates
df = pd.read_csv('stock_market_data.csv')
df['Date_dt'] = pd.to_datetime(df['Date'])

# 2. Sort chronologically per ticker using parsed datetime objects
df_sorted = df.sort_values(['Ticker', 'Date_dt']).reset_index(drop=True)
records = []

for ticker, grp in df_sorted.groupby('Ticker'):
    g = grp.copy().sort_values('Date_dt').reset_index(drop=True)
    
    # Target: Next-day close-to-close percentage return (t to t+1)
    g['Next_Day_Return'] = ((g['Close_Price'].shift(-1) - g['Close_Price']) / g['Close_Price']) * 100
    g['Target_Date'] = g['Date_dt'].shift(-1)
    
    # Strictly lagged predictor features (available at or before session t close)
    g['Lag1_Return'] = ((g['Close_Price'] - g['Close_Price'].shift(1)) / g['Close_Price'].shift(1)) * 100
    g['Lag1_Intraday'] = ((g['Close_Price'] - g['Open_Price']) / g['Open_Price']) * 100
    g['Lag1_Volatility'] = ((g['High_Price'] - g['Low_Price']) / g['Open_Price']) * 100
    g['Lag1_Volume_Log'] = np.log1p(g['Volume'])
    g['SMA5_Return'] = g['Lag1_Return'].rolling(window=5).mean()
    g['Month'] = g['Date_dt'].dt.month
    
    records.append(g)

feat_df = pd.concat(records, ignore_index=True)
feature_cols = ['Lag1_Return', 'Lag1_Intraday', 'Lag1_Volatility', 'Lag1_Volume_Log', 'SMA5_Return']
common_req_cols = ['Next_Day_Return', 'Target_Date', 'Lag1_Return', 'Lag1_Intraday', 'Lag1_Volatility', 'Lag1_Volume_Log', 'SMA5_Return', 'Month']

# Common evaluation population eligibility filter
clean_df = feat_df.dropna(subset=common_req_cols).reset_index(drop=True)

# 3. Datetime-based Chronological 80:20 Train-Test split with 1-session boundary purge
unique_dates = sorted(clean_df['Date_dt'].unique())
split_idx = int(len(unique_dates) * 0.8)
train_dates = set(unique_dates[:split_idx])

train_df = clean_df[clean_df['Date_dt'].isin(train_dates)].reset_index(drop=True)
max_train_target_date = train_df['Target_Date'].max()

# Purge: test features start strictly AFTER the maximum training target realization date
test_df = clean_df[clean_df['Date_dt'] > max_train_target_date].reset_index(drop=True)

print("=== Chronological Split & Boundary Purging Audit ===")
print(f"Total Supervised Observations: {len(clean_df):,} ({clean_df['Date_dt'].nunique()} dates x 20 stocks)")
print(f"Training Feature Dates:       {train_df['Date_dt'].min().strftime('%Y-%m-%d')} to {train_df['Date_dt'].max().strftime('%Y-%m-%d')} ({train_df['Date_dt'].nunique()} dates, {len(train_df):,} rows)")
print(f"Training Target Dates:        {train_df['Target_Date'].min().strftime('%Y-%m-%d')} to {max_train_target_date.strftime('%Y-%m-%d')}")
print(f"Purged Boundary Date:         {pd.to_datetime(unique_dates[split_idx]).strftime('%Y-%m-%d')} (1 session isolated to eliminate label-to-feature overlap)")
print(f"Testing Feature Dates:        {test_df['Date_dt'].min().strftime('%Y-%m-%d')} to {test_df['Date_dt'].max().strftime('%Y-%m-%d')} ({test_df['Date_dt'].nunique()} dates, {len(test_df):,} rows)")
print(f"Testing Target Dates:         {test_df['Target_Date'].min().strftime('%Y-%m-%d')} to {test_df['Target_Date'].max().strftime('%Y-%m-%d')}")
print(f"Temporal Non-Overlap Check:   max(Train Target) < min(Test Feature) -> {max_train_target_date < test_df['Date_dt'].min()}")

4. Simple Linear Regression (Lag1_Return $\rightarrow$ Next_Day_Return)¶

We model forward next-session return as a linear function of the prior session's return: $$\hat{y}_{t+1} = \beta_0 + \beta_1 \cdot \text{Lag1\_Return}_t$$

In [3]:
# Define univariate feature matrix and target vectors
X_train_s = train_df[['Lag1_Return']]
y_train = train_df['Next_Day_Return']

X_test_s = test_df[['Lag1_Return']]
y_test = test_df['Next_Day_Return']

# Fit Ordinary Least Squares (OLS) model
slr = LinearRegression()
slr.fit(X_train_s, y_train)

# Generate out-of-sample predictions
y_pred_slr = slr.predict(X_test_s)

print("=== Simple Linear Regression (OLS) Parameters ===")
print(f"Intercept (β₀):             {slr.intercept_:.6f}")
print(f"Coefficient (β₁, Lag1_Ret): {slr.coef_[0]:.6f}")
print(f"Fitted Equation:            Next_Day_Return = {slr.intercept_:.4f} + ({slr.coef_[0]:.4f} * Lag1_Return)")

10. Academic Findings & Performance Analysis¶

  1. Model Performance vs. Zero-Return Baseline:
    • The Zero-Return Baseline ($\hat{y} = 0$) achieves an out-of-sample $\text{MAE} = 1.1985\%$ and $\text{RMSE} = 1.6247\%$.
    • Simple Linear Regression achieves $\text{MAE} = 1.2005\%$, $\text{RMSE} = 1.6264\%$, and $R^2 = -0.003635$.
    • Multiple Linear Regression achieves $\text{MAE} = 1.2004\%$, $\text{RMSE} = 1.6272\%$, and $R^2 = -0.004658$.
  2. Model Generalization & Negative $R^2$:
    • Both linear regression models yielded slightly negative $R^2$ scores on this independent test set ($-0.003635$ for SLR and $-0.004658$ for MLR), and neither outperformed the naive Zero-Return Baseline in out-of-sample MAE or RMSE.
    • Rather than confirming or proving a market-wide theoretical hypothesis such as the Weak-Form Efficient Market Hypothesis, this empirical result demonstrates that the specific linear combinations of lagged price momentum, intraday spreads, and volume tested here failed to extract usable linear predictive signal over a zero-return forecast on this particular out-of-sample dataset and evaluation period.
  3. Rigorous Validation Without Leakage:
    • Enforcing strict chronological order with parsed datetime indices, separate per-ticker lag calculations, explicit target dates, common eligibility filtering, and a 1-session boundary purge ($2026-03-06$) eliminates all forms of forward-looking bias, target leakage, and test contamination.
