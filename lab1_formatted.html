Experiment 01: Build Data Warehouse / Data Mart & Design Dimensional Data Models

1. Aim / Objective

To design and implement a Data Warehouse for the Stock Market dataset using three dimensional modelling techniques: Star Schema, Snowflake Schema, and Fact Constellation (Galaxy) Schema. The warehouse stores daily trade facts (Open, High, Low, Close prices, Volume, Daily Return) together with conformed time, stock, and exchange dimensions.

2. Theory

2.1 Data Warehouse

A Data Warehouse (DW) is a subject-oriented, integrated, time-variant, and non-volatile collection of data used to support management decision-making (Inmon, 1992). It separates analytical workloads from operational databases (OLTP) by storing pre-aggregated, historical data in a schema optimised for read-heavy OLAP queries.

2.2 Star Schema

The Star Schema is the simplest dimensional model. A central Fact table (Fact_DailyTrades) holds quantitative trade metrics and foreign keys to denormalized Dimension tables (Dim_Time, Dim_Stock, Dim_Exchange). Queries involve at most one join per dimension, delivering the fastest analytical performance.

2.3 Snowflake Schema

The Snowflake Schema extends the star by further normalizing dimension tables. Dim_Stock_Snowflake references a separate Dim_Sector sub-dimension, eliminating redundant sector/industry storage at the cost of additional joins.

2.4 Fact Constellation (Galaxy) Schema

The Fact Constellation supports multiple fact tables sharing conformed dimensions. Here, Fact_DailyTrades and Fact_QuarterlyFinancials both reference Dim_Time and Dim_Stock, enabling cross-fact drill-across OLAP queries.

4. DDL Scripts

4.1 Star Schema DDL

-- ══════════════════════════════════════════════
--  STAR SCHEMA DDL
-- ══════════════════════════════════════════════

CREATE TABLE IF NOT EXISTS Dim_Time (
    Time_Key    INTEGER PRIMARY KEY AUTOINCREMENT,
    Date        DATE    NOT NULL UNIQUE,
    Day         INTEGER,
    Month       INTEGER,
    Quarter     INTEGER,
    Year        INTEGER,
    Day_of_Week TEXT,
    Is_Weekend  BOOLEAN
);

CREATE TABLE IF NOT EXISTS Dim_Stock (
    Stock_Key   INTEGER PRIMARY KEY AUTOINCREMENT,
    Ticker      TEXT    NOT NULL UNIQUE,
    Company     TEXT,
    Sector      TEXT,
    Industry    TEXT,
    Market_Cap  TEXT
);

CREATE TABLE IF NOT EXISTS Dim_Exchange (
    Exchange_Key  INTEGER PRIMARY KEY AUTOINCREMENT,
    Exchange      TEXT    NOT NULL UNIQUE,
    Country       TEXT,
    Currency      TEXT,
    Time_Zone     TEXT
);

CREATE TABLE IF NOT EXISTS Fact_DailyTrades (
    Trade_ID            INTEGER PRIMARY KEY AUTOINCREMENT,
    Time_Key            INTEGER REFERENCES Dim_Time(Time_Key),
    Stock_Key           INTEGER REFERENCES Dim_Stock(Stock_Key),
    Exchange_Key        INTEGER REFERENCES Dim_Exchange(Exchange_Key),
    Open_Price          REAL,
    High_Price          REAL,
    Low_Price           REAL,
    Close_Price         REAL,
    Volume              INTEGER,
    Daily_Return        REAL,
    Intraday_Volatility REAL
);

4.2 Snowflake Schema DDL

-- ══════════════════════════════════════════════
--  SNOWFLAKE SCHEMA DDL
-- ══════════════════════════════════════════════

CREATE TABLE IF NOT EXISTS Dim_Sector (
    Sector_Key  INTEGER PRIMARY KEY AUTOINCREMENT,
    Sector_Name TEXT    NOT NULL UNIQUE,
    Industry    TEXT,
    Market_Cap  TEXT
);

CREATE TABLE IF NOT EXISTS Dim_Stock_Snowflake (
    Stock_Key   INTEGER PRIMARY KEY AUTOINCREMENT,
    Sector_Key  INTEGER REFERENCES Dim_Sector(Sector_Key),
    Ticker      TEXT    NOT NULL UNIQUE,
    Company     TEXT
);

CREATE TABLE IF NOT EXISTS Fact_DailyTrades_Snowflake (
    Trade_ID            INTEGER PRIMARY KEY AUTOINCREMENT,
    Time_Key            INTEGER REFERENCES Dim_Time(Time_Key),
    Stock_Key           INTEGER REFERENCES Dim_Stock_Snowflake(Stock_Key),
    Exchange_Key        INTEGER REFERENCES Dim_Exchange(Exchange_Key),
    Open_Price          REAL,
    Close_Price         REAL,
    Volume              INTEGER,
    Daily_Return        REAL,
    Intraday_Volatility REAL
);
